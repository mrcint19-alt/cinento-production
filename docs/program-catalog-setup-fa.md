# راه‌اندازی مدیریت برنامه‌های CINENTO

این تغییر روی شاخهٔ توسعه تهیه شده است. دیتابیس برنامه‌ها باید فقط پروژهٔ جدید `cinento-site-preview` در سازمان `CINENTO SITE` باشد. پایگاه‌های قبلی CINENTO و محیط سایت اصلی را تغییر ندهید.

## ترتیب اتصال

1. در پروژهٔ `cinento-site-preview`، فایل `supabase/migrations/20261106_site_programs.sql` را در SQL Editor اجرا کنید. این فایل جدول، سیاست‌های RLS و ۱۳ معرفی موجود را ایجاد می‌کند. اجرای مجدد ردیف‌های ویرایش‌شده را بازنویسی نمی‌کند.
2. در همان پروژه، بخش **Authentication → Users**، یک کاربر مخصوص مدیریت سایت بسازید. ورود به حساب داشبورد Supabase به‌تنهایی کاربر برنامهٔ سایت نمی‌سازد. UUID کاربر را بردارید و دستور `insert into public.site_catalog_admins(user_id) values ('UUID');` را با UUID واقعی اجرا کنید.
3. مقدار `CINENTO_CATALOG_ADMIN_IDS` را برابر همان UUID قرار دهید. `CINENTO_CATALOG_SUPABASE_URL` از **Project URL** و `CINENTO_CATALOG_SUPABASE_KEY` از **Publishable key** همان پروژه گرفته می‌شود. این سه متغیر باید در محیطی که قرار است مدیریت برنامه‌ها فعال باشد تنظیم شوند. کلید `service_role` و رمز دیتابیس نباید در این بخش استفاده شوند.
4. برای آزمون محلی، متغیرها را در `.env.local` قرار دهید و `npm run dev` را اجرا کنید. مسیر `/en/dashboard/programs` از همان داشبورد سایت قابل دسترس است؛ با حساب ساخته‌شده در Authentication وارد شوید. یک برنامهٔ آزمایشی را در حالت پیش‌نویس ثبت، ویرایش، منتشر و حذف کنید؛ نتیجه را در `/en/platforms` بررسی کنید.

در محیط Vercel Preview، طبق قفل امنیتی فعلی، همهٔ تغییرات نوشتنی مسدود است و فهرست عمومی نسخهٔ ثابت شاخه را نشان می‌دهد. برای فعال‌شدن مدیریت زنده باید انتشار و تنظیم متغیرهای محیطی در محیط مناسب جداگانه بررسی شوند. پیش از آن، سایت اصلی همان رفتار قبلی خود را دارد.

صفحهٔ عمومی بدون تنظیم دیتابیس نسخهٔ ثابت را نشان می‌دهد. پس از تنظیم دیتابیس، فهرست فقط از جدول `site_programs` خوانده می‌شود؛ اگر خواندن جدول خطا دهد، پیام خطا نشان داده می‌شود و دادهٔ قدیمی جایگزین نمی‌شود. فقط ردیف‌های منتشرشده برای عموم قابل خواندن‌اند.
